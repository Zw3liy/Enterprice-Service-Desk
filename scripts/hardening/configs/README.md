# Hardening configuration library

Drop-in configuration files installed by the `harden_*.sh` scripts in
the parent directory. Every file here is a **template**: the scripts
copy it into place (with a timestamped backup of anything it replaces)
and validate before reloading the affected service. Nothing here is
auto-applied to your host by existing in the repository.

## Manual-surface files

Three groups are deliberately **not** fully automated:

* **nginx/NPM snippets** — NPM's config is generated by its app; a
  script clobbering it would break running proxy hosts. `harden_edge.sh`
  prints exact instructions; the files are pasted/mounted, then verified
  with `nginx -t` before reload.
* **cloudflared/config.yml** — tunnel UUIDs/credentials are per-host
  secrets; the file is a template you fill in. Overwriting a live
  tunnel config automatically would cause an outage.
* **PAM (`pam-auth-update`)** — enabling `pam_faillock` changes the
  login stack; done by a human with a second session open (the script
  installs the policy file and prints the activation command).

## Customising

Edit the file here and re-run the owning script — it detects the
difference and reinstalls (backup first). The `90-enterprise-service-desk`
tag marks everything installed from this directory.
